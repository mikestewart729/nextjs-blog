title: "Following a Rust tutorial to build a terminal game based on Beast"
date: "2025-08-22"
---
Recently, as an exercise in better learning to work with Rust, I found and followed the tutorial titled _Learning Rust by Building the Old Terminal Game Beast from 1984_ by Dominik Wilkowski, which can be found on his blog [here](https://dominik-wilkowski.com/posts/learning-rust-by-building-the-old-terminal-game-beast-from-1984-part-1/). I found it to be an excellent tutorial and a very fun learning process. 

Rust has recently been gaining popularity and broad usage in the tech sphere for, among other reasons, its C-level performance (it's blazing fast) combined with its guaranteed memory safety (avoiding many of the pitfalls that plauge C based codes today). Furthermore, it is very easy to write unit tests directly in Rust, and its support for integration testing is also robust. I find the ease of writing tests in Rust to be a particularly attractive feature as a developer, for it streamlines the process of **test driven development (TDD)**, an approach to development wherein you define the tests your code should pass at the outset, and then develop code first to prevent the test from crashing (panicking in the case of Rust), and then to actually pass the test. TDD is something I've been utilizing more and more in my professional life, and I'm very happy to see it so seamlessly applicable in Rust development.

But back to Dominik's game tutorial! I really liked the structure of the tutorial. He highlights the thought process behind his decision making, explains Rust's unique peculiarities, and makes sure to indicate where the strengths of Rust lie throughout the process. He's also very good about highlighting the aspects of Rust which are, to say the least, unusual for someone coming from a Python background. (I bet some of you reading this have found the borrow checker and lifetime annotations to be more than a little confusing at first glance!) Being a tutorial for a game, there are even opportunities to introduce Rust's approach to concurrent programming (_Fearless Concurrency!_, per [The Book](https://doc.rust-lang.org/book/ch16-00-concurrency.html)), which surely will find more application as I continue to grow my skills as a developer. Overall, I'm very pleased with the pedagogy and what I've learned from Dominik Wilkowksi's tutorial. Thanks Dominik!

In the future, I hope to add features to [the game](https://github.com/mikestewart729/beast_rust), potentially including those suggested as further exercises at the end of the tutorial, but also possibly including anything I can imagine myself. I know I'm looking forward to seeing how I can use Rust to make something fun!
